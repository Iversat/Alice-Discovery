# Проверка Alice Discovery

Дата локальной проверки: **20 октября 2026**. Среда: Windows, Python 3.12.10, zeroconf 0.151.5.

Локально: **24 теста пройдено**, покрытие модуля — **87%**. Проверки Ruff и сборка sdist/wheel прошли.

## Автоматические проверки

```bash
python -m pip install -e ".[dev]"
python -m pytest --cov=multiroom_scanner --cov-report=term-missing
python -m ruff check .
python -m ruff format --check .
python -m pip check
python -m build
```

Проверены IPv4/IPv6, бинарные TXT-поля, обновление и удаление сервисов, несколько объявлений одного хоста, независимость снимка, отсутствие информации о сервисе, некорректные параметры, чистый JSON и закрытие ресурсов при ошибке и Ctrl+C.

Тесты подменяют сетевое наблюдение и не требуют реальных устройств. Матрица CI задаёт Windows/Linux и Python 3.11, 3.12, 3.14; подтверждением её прохождения служит конкретный запуск Actions.

## Реальная локальная сеть

Выполнено `python multiroom_scanner.py --duration 3 --json`. Получены **три объявления `_yandexio._tcp.local.`**, каждое с IPv4, IPv6 и TXT-свойствами. Полные адреса и идентификаторы домашних устройств намеренно не включены в публичную документацию.

Это проверяет обнаружение объявлений в конкретной сети. Она не подтверждает управление колонками, синхронное воспроизведение, работу во всех VLAN или обнаружение каждого устройства. Скрипт не подключался к объявленным портам.

## Воспроизведённые ошибки исходной версии

База: коммит `222d5b504871608a8d132d154a8eec2510783a53`.

1. Добавление сохраняло запись по имени хоста, а удаление искало по имени сервиса: исчезнувшая запись оставалась.
2. Метод update_service ничего не делал, поэтому изменённый порт не обновлялся.
3. Обработка IPv6 через inet_ntoa вызывала OSError.
4. TXT-значение с невалидным UTF-8 вызывало UnicodeDecodeError.

Эти сценарии покрыты регрессионными тестами.
